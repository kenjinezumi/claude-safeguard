claude-safeguard EXCEL ASSISTANT — INSTALLATION AND FIRST USE
Windows pilot, version 0.7.1

BEFORE YOU START
Use a work laptop and an organisation-approved Claude account with Claude Code access.
You need internet access during setup. Excel is useful for opening and reviewing
results, but the local calculation tools do not require Excel to run.
If your organisation restricts software installation, ask IT to install this package.
Do not turn off company security controls. This pilot has not yet been validated
end-to-end on Windows: rehearse with the supplied synthetic examples first.

FIX AN EXISTING INSTALLATION
1. Close Claude and download/extract this new ZIP into a separate folder.
2. Double-click Repair.cmd in the newly extracted folder.
3. When it says Package repaired, double-click Test-Installation.cmd in the ZIP folder.
4. If the local checks pass, open the desktop shortcut or Start.cmd.
Your workbooks and selected folder are preserved. Required guard/MCP settings and
dependencies are updated; unrelated settings are retained. Previous settings and
package files are backed up inside Launcher-Backups in the installed folder.
Install.cmd also chooses this repair automatically when an installation exists.
This also fixes the MCP dependency, hook failure handling and JSON encoding. An incomplete installation
still needs IT help. Close Claude before repair, then start a fresh session.

INSTALL — ONCE
1. Download claude-safeguard.zip.
2. In File Explorer, right-click the ZIP and choose Extract All.
3. Open the extracted claude-safeguard folder.
4. Double-click Install.cmd. Do not run it from inside the ZIP.
5. Leave the window open while setup works. It installs Claude Code if missing,
   Python if needed, and the local document/spreadsheet dependencies.
   Downloads can take several minutes. Read any installation prompts.
6. When it says Installed, close the installer window. Desktop shortcuts are ready.
   If it says Installation stopped, do not continue to a demonstration. See below.
7. Double-click Test-Installation.cmd in the extracted folder. This checks the
   installed runtime and runs synthetic offline tests. Keep the window open if
   it fails. A PASS still requires the live rehearsal below; it does not test
   Microsoft sign-in or Claude hook execution. No work documents are needed.
Setup requires Claude Code v2.1.295+ and tries to update an older installation.

CHOOSE YOUR WORKING FOLDER
1. Create a folder containing only approved, de-identified working copies.
   Include only subfolders you also want Claude to browse.
2. Double-click claude-safeguard - Select working folder on your desktop.
3. Select that folder and confirm your choice.
Claude can list filenames inside it and import XLSX copies for analysis.
It does not edit the originals. Keep sensitive originals outside this folder.
Selecting a folder does not anonymise its contents or guarantee PII detection.

OPEN CLAUDE
1. Double-click claude-safeguard on your desktop, or Start.cmd in the extracted ZIP folder.
2. Follow the browser sign-in prompt using your approved work account, if asked.
3. Accept the workspace trust prompt only for this installed package.
4. Approve the bundled local claude_safeguard tool when prompted.
5. Type /mcp to check claude_safeguard is connected. Type /hooks to check the
   SessionStart, UserPromptSubmit and PreToolUse hooks are present.
   If either check fails, ask IT before entering work data.
6. Start typing your request in ordinary language. You do not need to copy the
   analyst prompt: CLAUDE.md is installed and loaded automatically.

FIRST PRACTICE — SYNTHETIC DATA ONLY
Use the Examples folder supplied in the ZIP as your selected working folder.
It contains synthetic source data, a template and expected outputs.
Ask:
  Browse my approved folder. Import Synthetic-Financial-Data.xlsx and inspect it.
Then:
  Create a GBP budget-versus-actual dashboard grouped by Department. Use Budget
  and Actual as the amounts and Currency as the currency column. Reconcile totals.
Expected totals: budget 3,500; actual 3,300; variance -200.
For template practice, follow Examples/START-HERE.txt.
The example outputs were generated by local tests, not a live Claude rehearsal.
Before a demonstration, verify in a fresh Claude session:
- /mcp shows the bundled tool connected and /hooks shows the three package hooks.
- The synthetic dashboard produces 3,500 / 3,300 / -200 and opens correctly in Excel.
- Template practice produces 1,500 for Newsroom and 1,800 for Operations.
- A synthetic prompt containing test@example.invalid is blocked.
- A request to use Bash or read an unapproved file is denied by the safeguard.
Ask IT to test hook-crash/timeout blocking in an isolated test copy as described
in VALIDATION.txt. Do not tamper with a working installation to test this yourself.
For SharePoint, finish sign-in and import a synthetic policy and workbook from
the configured folder. If any live check fails, stop the rollout and keep the
error code. Do not paste real work content or credentials for troubleshooting.

SHAREPOINT POLICIES AND WORKBOOKS
After installing/updating, open Connect-SharePoint.cmd in the extracted package.
First use needs the completed sharepoint-settings.json file from your Microsoft 365
administrator. Select it, confirm the approved source, and sign in with Microsoft.
The organisation setup is explained in SHAREPOINT-SETUP.txt. It needs an Entra app
registration and a read grant on the selected site; no hosted app is deployed.
Start a fresh Claude session and ask:
  Check my SharePoint connection, then browse the approved SharePoint folder.
  Import the policy at the exact returned path and summarise the prepared text.
  Import those monthly workbooks and create a budget-versus-actual dashboard.
SharePoint documents are downloaded and checked locally before content is returned.
The tool cannot edit/upload files on SharePoint. Outputs stay in local Workbooks.
Only material already approved for Claude belongs in the configured source.
Direct document URLs within that folder also work. For short sharing links, browse
the approved folder instead. Never paste passwords, tokens or login URLs into chat.
If sign-in expires, run Connect-SharePoint.cmd again. To sign out, close Claude and
run Disconnect-SharePoint.cmd. Existing imports/results remain on the laptop.

The local Prepare file shortcut remains available for downloaded/local documents.
It returns an exact prepared filename; do not guess names or change file extensions.
The selected local workbook folder and installed Approved-Data serve separate roles.

IF A FILE CHECK FAILS
Run Check-File.cmd from the extracted NEW package after install/repair. It opens
a local file picker in the installed Approved-Data and reports a code; it uploads
nothing and does not start Claude. Share only the code when troubleshooting.
SG-NOT-FOUND: the exact requested path is missing; use Prepare file's actual name.
SG-FOLDER: the file is outside the installed Approved-Data; use Prepare file.
SG-TYPE / SG-ENCODING: convert/export supported content to UTF-8 TXT/CSV locally.
SG-LINK: linked/cloud-placeholder path; use a downloaded ordinary local copy.
SG-SENSITIVE: a heuristic matched, possibly a policy label or contact details.
  Review locally; do not bypass the guard or automatically remove policy labels.
SG-ACCESS / SG-READ: local access or open-file problem; check the copy locally.
SG-CHECK-* / SG-DIAGNOSTIC: check failure; close Claude and give the code to IT.
A passing check is not anonymisation or permission to upload sensitive content.

EVERYDAY REQUESTS
- Find this month's workbooks in the approved folder and inspect their sheets.
- Propose how to combine the tables; flag unmatched accounts and duplicate keys.
- Build a dashboard by programme, showing budget, actuals and cost variances.
- Fill this template using the source tables. Show uncertain mappings before writing.
- Produce the next month's report on a new sheet and explain changes in totals.
State the period and currency. Claude should ask where a material choice is unclear.

FIND YOUR RESULTS
Claude returns a new workbook filename after each edit. Use the LAST filename.
Press Windows+R, paste this path, and press Enter:
  %LOCALAPPDATA%\claude-safeguard\Workbooks
Open the result in Excel. Recalculate formulas and review before sharing.
Opaque filenames are intentional; you may rename a copy elsewhere for circulation.
For non-Excel documents, use claude-safeguard - Prepare file and review the
extracted text locally before approving it. That workflow does not preserve layout.

COMMON PROBLEMS
- No Install.cmd: extract the ZIP first; check you opened the inner package folder.
- Windows or company policy blocks the script: ask IT. Do not disable protections.
- WinGet unavailable: IT needs to enable Windows App Installer for automatic Python
  installation, or prepare the supported Python installation centrally.
- Installation stopped / dependency download failed: check internet and ask IT.
  The installer does not roll back partial installs. Do not delete folders blindly.
- Already installed: run Install.cmd or Repair.cmd from this new extracted ZIP.
  It updates scripts, dependencies and required guard/MCP settings; data and unrelated settings are retained.
- Claude is not recognized: the launcher now finds the native executable directly.
  Use the desktop shortcut or Start.cmd; no manual PATH command is needed.
  Typing bare claude in a separate terminal still depends on that terminal's PATH.
- Repair says incomplete: setup previously stopped before all components were
  installed. Ask IT to complete setup without deleting your working files.
- Tool disconnected: check /mcp and ask IT to inspect the local Python dependency
  installation. Never send full work-data logs or transcripts for troubleshooting.
- File blocked: review it locally for sensitive fields, unsupported features or size.
  Do not paste the blocked data into chat or disable the hook to force it through.
- Formula not updated: open the result in Excel and recalculate. The local tool
  writes formulas but does not provide Excel's calculation engine.

CAPABILITIES AND LIMITS
Supports common XLSX reading, editing, cleaning, joins, summaries, formatting,
charts, financial dashboards and template filling. VBA, Power Query, slicers,
native pivot creation and exact advanced-object preservation are not implemented.
This user-installed pilot can be disabled; it is not an OS sandbox or complete DLP.
See README.txt and VALIDATION.txt for limits and the testing actually completed.
