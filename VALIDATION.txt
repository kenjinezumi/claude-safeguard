CONFIRMED DEFECTS CORRECTED
Fresh unpinned installation selected MCP 2.3.0; importing mcp.server.fastmcp raised
ModuleNotFoundError. Pinning to tested MCP 1.30.0 restores the server API.
Installer and repair now install tested core dependencies and run the real
synthetic protocol check before reporting success. Optional sign-in packages
are pinned separately and import-checked by Connect-SharePoint.cmd.

Previous settings lacked onFailure=block. Anthropic documents non-blocking
failures/timeouts by default for these events. Required prompt/tool hooks now
block on failure, and the launcher requires the documented minimum v2.1.295.
Exec-form arguments avoid shell parsing of Windows paths. Windows PowerShell
5.1's Set-Content UTF8 produces a BOM; Python now writes these JSON files without
one, and repair migrates existing BOM files with backups.

Additional corrections: bounded workbook reads, Windows reparse checks, import
cleanup after subprocess failure, missing dashboard categories/empty data,
consistent external-formula screening, and explicit many-to-many join refusal.

NOT EXECUTED / NO CLAIM OF PASS
- Fresh installation on Windows 10/11, Python 3.13 setup through WinGet, locked-down
  enterprise devices, antivirus/SmartScreen/proxy behaviour, ARM64 or offline use.
- Windows PowerShell 5.1, Forms pickers, COM shortcuts, Unicode profiles on Windows.
- Live Claude trust prompts, project hook activation, tool-name mapping, failure/
  timeout handling, global or managed settings interactions, resumed sessions.
- Microsoft OAuth browser sign-in, Windows DPAPI persistence, token refresh,
  Sites.Selected grants, Conditional Access or actual tenant download redirects.
- Excel opening/recalculation, visual chart fidelity and advanced workbook features.
- Comprehensive sensitive-data detection, hostile local users or complete sandboxing.
Passing simulated transport tests does not prove that a tenant will grant access.

WINDOWS ACCEPTANCE RUN — BEFORE STAFF ROLLOUT
1. Use a clean supported Windows account and the organisation-approved Claude
   account. Extract the ZIP and run Install.cmd. Do not delete existing user data.
2. Run Test-Installation.cmd. It uses the installed Python for the installed MCP
   smoke check and package offline tests. Platform-specific skips are shown.
   This check does not send anything to Claude or Microsoft. Setup/repair downloads
   and Claude --version are separate operations. Capture failure codes only.
3. Open the desktop shortcut. Verify /hooks and /mcp, accept only the package's
   trusted workspace/local server. Run the synthetic dashboard/template examples
   in START-HERE.txt. Check exact totals, styles/formulas and charts in Excel.
4. Verify allowed TXT reads, missing-file diagnostics, synthetic email refusal,
   and shell/unapproved-path refusal in that live session.
5. IT: use an isolated COPY with synthetic data to force a PreToolUse and
   UserPromptSubmit hook failure (missing script), then timeout. Verify Claude
   blocks the call/prompt. Restore the copy. Do not disable the production hooks.
6. IT: finish SHAREPOINT-SETUP.txt and provide settings. Staff run
   Connect-SharePoint.cmd, sign in, browse the configured source and import an
   approved synthetic policy and XLSX. Confirm out-of-scope access is refused,
   no remote file is edited, expired login requests sign-in, and results open.
7. Run Repair.cmd on a synthetic existing installation, then Test-Installation.cmd
   and a fresh Claude session. Verify old workbooks/folder selection are retained.
Record Windows, Claude and Python versions and the pass/fail result for each step.
A failure here means the package is not yet approved for staff rollout.
